## 1. 최신 범위와 목표

2026-10-22의 착수·ML 승인 후 제한 v1 두 모델의 실제 GPU 학습·평가와 저장 격자 ML dry-run을 마쳤다. 2026-10-26 사용자가 인간/봇 웹사이트와 Cloudflare 연동을 새로 요청해 **이 프로젝트 안에서 웹 대결과 관리자 사진 업로드도 구현한다.** 이전 ‘참가자 웹사이트는 별도라 만들지 않는다’와 ‘5개 문제은행’ 조건은 이번 명시 요청으로 대체했다.

현재 웹은 사람이 3명 이상, 나무가 3그루 이상, 건물 있음, 연못 있음의 **4종**이다. 서로 다른 관계 그룹의 독립 사진 9개로3×3을 만들고 인간·봇에 같은 사진 순서와 공통 시작 시각을 적용한다. 정답 수는 사람/건물/연못2~4칸, 나무3~4칸이며 서버만 실제 답을 안다. 한 참가자가 한 문제로 대결한다. 최신 사용자 승인으로 remote는 다음 참가자도 같은 방·코드·표시 화면/PC 연결을 재사용하며 인간이 준비/시작한다. 새 방은 초기 설정·복구에만 필요하다. legacy는 한 방 한 판을 유지한다. 상세 계약은 [INTEGRATION](INTEGRATION.md)을 따른다.

웹 기능 구현과 부스 완료는 다르다. v1의 나무 과선택·연못 미검출, 약40% 미달성과 ONNX/Pi 미완료를 공개한다. 학교 최종 평가는 최신 사용자 결정으로 이번 행사 범위에서 제외한다. 기존 사이트version2 게시 succeeded와 `human.marulee.dev`·`bot.marulee.dev`의 provider/native/SSL active 및 당시 공개HTTPS/API8개는 확인 이력이다. 사이트version2는 ML calibration v2 학습을 뜻하지 않는다. 10/27 원격 패드 확장 이후 실제 게시 버전·GPU 두 방·A/B 브라우저 화면 결과는 [STATUS](STATUS.md)를 정본으로 삼는다.

이어 사용자가 웹에서 임의 사진을 내려받아 운영 사이트에 넣고 직접 시험하도록 요청했다. 운영 공개 사진은 기존 Kaggle 로컬 데모와 분리한 `data/booth/public-web-v1/` 및 신규 `public-web-v2/`에서 출처·공개 사용 근거·원본 그룹·시각 라벨을 관리한다. 학교 사진은 사용하지 않는다. 실제 확보·업로드 수량과 네 유형 준비성·사진 표시·브라우저 점검은 STATUS에서 확인하며 다운로드 시도만으로 운영 적용 완료라고 보고하지 않는다.

최초v1 공개 은행의 확보·검토 이력은 Public domain/CC0 **24장·6,063,549 bytes·24원본 그룹**이다. 최신v2 추가22장과 운영 총46장은 위 최신 확정 진행을 따른다. 로컬 라벨 기준으로 사람3명이상 P8/N11/U5, 나무3그루이상 P9/N11/U4, 건물 P8/N9/U7, 연못 P7/N17/U0으로 네 유형의 최소 구성을 충족한다. 전체 프레임 JPEG 정리·EXIF/comment 제거·최종 SHA/디코딩을 확인했으며, 시각 라벨은 단일 Codex 검토다. 이어 운영 업로드24/24·기존 동일사진0과 원격 서버4종 ready를 확인했다. 네 유형의9사진 디코딩/독립 SHA·원본그룹/두 호스트 동기화/정답범위 검사와 Chrome 별도 QA 방의 실제9사진 표시도 통과했다. 정답 선택·제출·ML 봇 실행은0이며 이는 직접 사진을 시험할 준비가 된 상태이지 모델 성능/실클릭 완료가 아니다. 실제 결과는 STATUS와 `runs/site-publish/public-photo-*-verification.json`에 기록한다.

### 10/27 후속 요청: 컴퓨터 브라우저·A/B remote 운영

기존 Android 태블릿4대 운영 승인 뒤 사용자가 인간/AI 표시를 컴퓨터 브라우저에서 운영하도록 변경했다. 실제 컴퓨터 대수·화면 배치는 아직 확정하지 않았다. 기본 remote는 A/B 구역과 `?lane=A/B`·역할/구역별 세션을 제공한다. 각 구역을 처음 독립 방/코드로 연결하고 참가자 교체 때 그 방을 재사용한다. 경기별 승자와 시각은 독립이다. AI 표시 화면의 `bot` 역할은 읽기 전용이고 PC는 별도 `engine` 역할로 heartbeat·불변 ML 선택 계획 업로드를 담당한다. 다른 구역 코드와 잘못된 역할의 행동을 거부한다.

최신 화면 운영 기준은 컴퓨터 브라우저다. Chrome은 권장 기준이며 실제 운영 컴퓨터의 대수·OS/브라우저 버전·화면 방향/해상도·동시 네트워크 성능은 미확인이다. 이전 태블릿 승인과 viewport 검사는 이력이며 현재 컴퓨터 배치의 현장 검증이 아니다. PC ML→서버 선택→읽기 전용 표시와 A/B·고정 코드·다음 참가자 절차를 유지한다.

PC가 보낸 불변 계획을 서버가 권한·중복·회차/생존 조건으로 고정하고250ms 일정으로 재생하며, bot 응답에만 예정 번호를 제공한다. remote AI 표시는 유효 계획 뒤500ms 상태조회·50ms 서버시계 갱신으로 체크를 그리고 계획 없는 진행 단계는125ms 조회를 사용한다. 수동 타일·준비·제출 버튼은 없다. 화면에 실제 마우스/터치 입력을 주입하는 방식이 아니다. `viewerConnected`는 최초 표시 연결 등록이며 사진 로드나 현재 화면 생존을 증명하지 않는다. 엔진 생존은15초 heartbeat로 별도 검사한다. 인간/표시 화면 모두 사진 전체 contain과 기존9사진 로딩 검사를 유지한다. 서버 Node30·TypeScript·UI ESLint·실제 localhost remote HTTP1개19.126717초를 통과했으며 실제 GPU 두 방·공개 배포·A/B 브라우저/부하 검증은 STATUS의 최종 결과로 구분한다.

앞선 웹 게시 작업에서 TypeScript·대상 프런트엔드 ESLint, Python99개(11.136초), Node18개와 로컬HTTP1개(test body 약3.2707초·runner 약8.9763초)가 통과했고 로컬34장 D1/R2 가져오기도 확인했다. 당시 root IAB 홈·인간 방 생성의 접근성 확인 후 네이티브 Chrome URL 확인 실패로 화면 시험을 중단했으며 우회하지 않았다. 앞선v1 공개 사진 작업에서는 Chrome 확장으로 배포된 인간 화면을 확인했다. 브라우저 연결/사진 표시 검사와 **ML 봇의 실제 캡처·클릭·제출, 물리 보정·간격 검증**은 별개이고 후자는 아직 미완료다. 저장 RGB·API·브라우저 점검을 실기기 봇 완료로 합치지 않는다. 이번 최종 검사 수량과 운영 반영은 STATUS를 따른다.

이전v1 공개사진 단계의 전체 Python105개(12.020초)·compileall·pip check 통과도 이력으로 보존한다. 운영 키를 동일 권한으로 갱신한 환경revision3은 기존 사이트version2로 재게시 성공했으며 소스·모델을 바꾼 게시가 아니다. 키는 메모리/stdin/서버 비밀 환경에만 두고 파일·인자·로그에 남기지 않았다.

이전v1 원격 출제/사진 QA는 격리된 방7개 요청으로 네 유형을 모두 확인했고 정답을 제출하지 않았다. Chrome 화면 QA도 별도 방에서 봇 역할 참가/준비 후 시작해9사진이 실제로 로드됨을 확인하고 전체 화면 PNG를 기록했다. 실제 ML 봇은 실행하지 않았으며 선택/제출도 하지 않았다. 사용자가 열어둔 원래 대기실은 시작하지 않았으므로 본인이 새 사진으로 시험할 수 있다.

## 4. 데이터와 모델 보존

기존 확보 자료는 COCO64·ADE32·Places38로 총134장이다. 존재 정본70장은 train41/val14/test15, 사람 검출 적격38장은 train17/val3/test18이다. unknown은 loss/평가에서 제외하고 군중·불완전 bbox를 검출 fit/평가로 승격하지 않는다. 단일 AI 검토와 작은 표본, ImageNet/COCO 사전학습의 한계를 공개한다. 자세한 수량·규칙은 [DATASET](DATASET.md)와 [DATASET_CANDIDATES](DATASET_CANDIDATES.md)를 따른다.

`configs/limited-baseline-v1.json`과 학습 전 프로필에 seed42·각1epoch·예산·동결 범위·임계값을 고정했다. 존재 모델은 상한64/실제41장·batch8·lr0.001·sigmoid0.5, 사람 모델은 상한32/실제17장·batch2·lr0.0001·score0.5·NMS0.45다. 두 특징 추출부와 BN 통계는 학습 전후 해시가 같았다. checkpoint/report는 `models/checkpoints/presence-limited-v1/`, `person-limited-v1/`에 보존한다.

v1 test를 이미 봤으므로 웹 데모 결과나 학교 결과에 맞춰 가중치·임계값·라벨 기준을 재튜닝하지 않는다. 기존 test 사진을 통합 동작 확인에 사용했다면 그 시도를 새 독립 정확도 평가로 세지 않는다. 학교 사진은 원본·크롭·증강까지 개발 train/val·모델 선택·조기 종료·예산/전처리 튜닝에서 제외한다. 웹 채점용 라벨은 모델 입력이 아니다.

이번 웹 공개 시연 사진도 운영 출제용으로 분리하고 학습·개발 검증·잠금 audit에 자동 편입하지 않는다. 모델 예측을 보고 쉬운 사진만 골라 목표 승률을 만드는 작업이 아니다. 사진별 명시적 양성/음성·미확인, 원본/연속 촬영/크롭 그룹, 출처 URL·저작자·공개 사용 근거와 SHA를 보존한다. 사람/건물/연못은 최소4양성7음성, 나무3그루 이상은4양성6음성의 독립 그룹을 확인해 모든 정답 수 범위를 출제할 수 있게 한다. 준비 여부는 실제 서버 검사로 확인한다.

나무3그루 이상을 존재 점수로 대신하거나 숲을 정확히3그루라고 라벨링하지 않는다. `tree_model.py`는 공식 Grounding DINO Tiny를 revision/hash 고정해 로컬 실행한다. 약689MB는 Git 제외·프로젝트/학교 추가 학습 없음이며 고정 프롬프트/score/NMS·LazyTree 로드를 사용한다. 초기 단일 사진 후 저장 RGB9타일 나무 문제도 GPU 실행했지만 선택 `[]`와 정답 `[0,1,4,6]`이 불일치했다. 충분한 계수 성능·학교·40% 달성이 아니다.

## 5. PC 원격 엔진과 legacy 입력
## GPU 예약과 사진 준비 후 출발

기본 remote의 인간 시작 요청은 `{expectedRevision}`을 보내 먼저 `queued`에 들어간다. 이때 `startRequest={id,requestedAt,expiresAt}`를 표시하고 회차는 그대로이며 `roundId/startAt/deadlineAt/topic=null`, `tiles=[]`다. PC가 GPU 차례를 확보한 뒤 `begin`으로 새 round를 `loading`에 만들고 인간/AI 표시의 숨긴9장 디코딩과 PC9장 RGB 준비를 기다린다. 같은 준비 epoch의 세 ACK 뒤에만 공통2초 카운트다운을 확정하며 준비 대기에는 시간0·문제/사진 비공개를 유지한다. 출발 때 같은 이미지/RGB를 재사용하고 모델 추론을 시작하며 반환 후 GPU를 해제한 뒤 A/B 선택은 독립 진행한다. 두 방의 절대 출발 시각이나 모든 네트워크/렌더링 지연이 같아진다는 보장은 아니다. 실제 적용 버전/검사는 STATUS를 따른다.

인간은 `cancel-start {requestId}`로 출발 대기를 취소하고 같은 방에서 다시 시작할 수 있다. 수동 취소·PC 연결 만료·PC 오류·대기 만료의 서버 사유를 구분한다. 대기 제한120초와 사진 준비60초는 운영 가안이다. 새 queued/취소/재요청의 revision과 요청ID를 비교해 오래된 상태·실패 알림이 새 요청을 덮지 못하며, 다음 참가자도 동일 방/코드를 유지한다. 새 출발은 `gpuReservationSupported=true`·`imageBarrierSupported=true`인 protocol3 PC 실행기와 준비 계약을 요구한다. 구형 실행기는 업데이트/재시작을 안내하며 이미 진행하던 구형 라운드 완료·legacy의 기존 시작과 구분한다.

예약으로 경기 중 GPU 경합 대기를 타이머 시작 전으로 옮기며 사전 정답 추론·사후 시간 보정·임의 오답은 없다. 모델/전처리/임계값·학교 사용·최소0.25초 선택은 유지한다. UI 회차/비밀필드/오류20개·TypeScript·대상 ESLint를 통과했고 서버/Python 통합·실제 GPU/브라우저·최종 배포/가동 결과는 STATUS를 따른다. 기존 대기/추론 기록에는 active 상태 조회 HTTP도 포함되므로 순수 GPU 시간으로 해석하지 않는다.


기본 운영은 **Start-Alpha-Remote.cmd**다. PC가 존재·사람·나무 모델을 CUDA에 한 번 불러오고 지속 콘솔에서 숨긴 `A CODE8` / `B CODE8` 입력을 받는다. 초기 A/B 방을 만들고 표시 화면/PC를 한 번 연결한다. 이후 인간이 다음 참가자 준비를 누르면 worker는 같은 engine token/heartbeat로 다음 lobby에서 준비하고, 인간이 시작한 새 round의 RGB를 다시 판별한다. 다른 구역은 계속 진행한다. 새 방·새 코드는 초기 설정·복구에만 필요하다. 모델은 공유하고 GPU 추론은 잠금으로 직렬화하므로 두 방 대기가 같다고 가정하지 않는다. 재사용 지원 버전의 실제 가동/재기동·반복 검증은 STATUS를 따른다.

### 기본 운영 순서 (이전10/28 준비에서 갱신)

이전 최초 가동 요청에서10/27 보이는 원격 콘솔을 실행했다. 아래7.297초는 당시 기록이고 최신 가동은 STATUS를 따른다. `runs/remote-engine/20261027-085448-1262f33b/startup.json`에서 remote/cuda·models_loaded_once=true·모델 로드7.297초와 실행 프로세스 생존을 확인했다. 사용자 입력용 콘솔을 켜 두고 코드 입력을 기다리며 중복 실행하지 않는다. 모델 로드와 A/B 방의 PC 준비는 별개로, 해당 새 코드를 입력한 뒤에야 각 방과 연결된다. 이번 요청의 자동 코드 입력·새 사진 추론·경기 시작은0회다. 현재 실가동 기록·프로세스 상태는 STATUS가 정본이다.

이 순서는 컴퓨터 브라우저 운영 안내이며 실제 컴퓨터 대수·브라우저/버전·화면 배치·동시 네트워크 리허설은 아직 미확인이다. 이전 PC viewport 검사와 기존 CUDA 연결 시험을 현장 시험으로 확대하지 않는다.

`run_remote_engine.py`는 기본 dry-run이고 `--execute`에서 실제 engine 참가·heartbeat·선택·제출을 수행한다. 운영용 cmd는 `--execute`를 명시한다. remote는 사용자가 승인한 HTTPS 행동 경로이며 F8 좌표 보정·화면 캡처·OS 마우스·브라우저 제어가 필요하지 않다. 공개 타일 URL은 동일 문제의 사진 바이트를 가져오는 전송 경로로만 사용한다. 메타데이터를 버리고 실제9장 RGB와 공개 질문만 ML에 넣으며 URL/ID·파일명·정답·실제 정답수로 풀지 않는다.

엔진은 **경기별** 고정 예측1회 뒤 선택 계획1회 업로드로250ms 재생·논리 제출1회를 맡긴다. 서버의 간격·라운드·권한·순서 검사와0개 예측 그대로 제출을 유지한다. 임의 타일·정답 반전·상위k 강제 선택은 없다. 첫 정답/경기 종료 시 그 경기의 남은 행동을 취소하고, 오답 자동 재추론 없이 결과를 기다린다. next 이후 같은 연결로 준비하고 새 start의 새 round만1회 판별한다. 이전 round를 새 참가자의 문제로 재제출하지 않는다.

실제 CUDA 두 방 연결 검증은 `runs/remote-booth-local-v2/verification.json`의 passed=true다. A 건물 선택 `[0,2,3]`·ACK 후 다음 송신 최소1.094초, B 나무 선택0개였으며 두 방 모두 오답 후90초 timeout으로 정상 종료했다. 이것은 프로토콜/실제 모델 연결 확인이고 정답 성공·독립 정확도 평가가 아니다. 물리 패드는0대이며 공개 배포·실기기 표시/재연결·부하 결과는 STATUS를 따른다.

최종 보고는 모델로드·최대3병렬사진다운로드·GPU추론/예약대기·계획업로드/ACK·서버예정선택/제출·실제상태/화면관측을 구분한다. 계획예정250ms를 실제클릭/렌더링실측으로 쓰지 않는다. 서버 선택 수락·브라우저 표시·실제 OS 클릭은 서로 다른 측정이며 remote 성공을 물리 클릭 성공으로 보고하지 않는다. 좁거나 낮은 화면용 live CSS는 intro/보조 영역을 접고 질문·9타일·제출/표시 상태가 viewport에 들어가도록 남은 높이에 격자를 맞춘다. 실제 표시 측정·실행 명령·모델/설정 해시·최종 게시 버전은 STATUS/SETUP을 따른다.

### legacy 화면 캡처·물리 마우스

이전 클릭 미동작 진단은 로컬 `run_booth_bot.py` 프로세스와 실측 `.local.json` 부재였다. 이 legacy 경로에서 웹 ready는 화면 준비 표시였고 지속 엔진 생존 검사가 아니었다. legacy 사용 시 Start-Alpha-Bot.cmd의 사용자 F8 물리 좌표 보정·`calibrated=true`·`--execute`가 필요하며, 모델/창 전면/질문 보호 영역을 검사한다. 기존 `ALPHA BOT | CAPTCHA` 제목 검사 문자열·600×600 격자/간격8px은 legacy에 유지하고 remote에는 반응형 레이아웃을 적용한다.

legacy는 화면 RGB만 모델에 넣고 최종 선택·제출을 OS 마우스로 수행한다. 선택/제출 HTTP 우회 금지는 이 경로에 적용되며 새 remote의 승인된 동기화 선택과 구분한다. 기본 dry-run·`--rounds 1`·고정 예측1회, 연속 실제 타일 클릭 최소0.25초를 유지한다. 네이티브 Chrome URL 확인 실패 후 OS 제어를 중단한 이력과 실제 OS 클릭0회·Pi GUI 미검증을 보존한다. 임의 좌표를 보정 완료로 표시하거나 다른 입력 도구로 중단을 우회하지 않는다.

## 6. 40% 평가와 별도 v2

기존 `configs/calibration-target-v2.json`의 목표는 4정답·5오답 격자에서 대상별/인원 n별 8조건을 각각 약40% 성공하는 것이다. 실제 웹의 4종과 정답 수 범위는 달라졌으므로 이 설정을 웹 성능 보증으로 쓰지 않는다. 정답 k개는 평가기에만 있고 풀이기는 상위 k개 강제 선택 없이 실제 예측대로 선택한다. k개 모두 선택하고 나머지를 모두 제외해야 전체 성공이다.

기존 val 캐시 평가기는 `scripts/evaluate_grids.py`다. manifest·캐시·보고서·체크포인트·이미지 해시와 출처/그룹/분할을 검사하고 val만 사용한다. seed20261022로 조건별100 disjoint 격자를 요청했으나 건물만1개·0/1, 나머지7조건0개여서 모두 `insufficient_data`, `target_achieved=null`이었다. 이는 새 모델 추론이 아닌 기존 예측 재집계다.

v2를 진행하려면 새 Kaggle 그룹을 train/선택 val/미사용 audit로 먼저 나누고 라벨·격자 seed·표본 수·유한한 학습 예산 후보를 예측 전에 고정한다. `plan_validation_grids` 직접 사용 시 먼저 manifest 실제 검증을 수행한다. 사진/그룹 재사용을 독립 표본 수로 세지 않으며 서명 없는 캐시의 해시는 ML 실행 진정성을 증명하지 않는다.

학습 CLI는 test를 기본 평가하지 않는다. 직접 API 호환 기본은 `evaluate_test=True`이므로 비교에는 명시적으로 `False`를 준다. 선택 val로 후보를 고른 뒤 모델/설정 해시를 고정하고 새 audit를 한 번 평가한다. 기존 v1 test·학교 결과로 다시 맞추지 않는다. 정확도·계수 MAE·n별 오류·전체 집합 완전 일치·분모와 불확실성을 함께 보고한다. `TPR^k × TNR^(9-k)`는 독립/동일 성능 가정 계산이며 학교 실측값이 아니다.

## 7. ONNX·Pi와 행사 운영 평가

ONNX FP32 내보내기와 PyTorch 출력 동등성·검출 후처리·경계 n별 최종 선택 비교는 남아 있다. 이름·형상/dtype·색상/정규화·letterbox·sigmoid·NMS·계수·모델/프로필 해시를 같은 metadata로 기록한다. 정확도를 바꾸는 튜닝과 배포 오차를 고치는 수정을 구분한다.

Pi는 시리얼 셸 접속, OS/ARM64/RAM/Python, 저장 이미지 추론, 실제 그래픽 세션의 캡처/입력을 각각 검증한다. Windows에서 Pi 예시 설정이 dry-run에 통과하거나 PyAutoGUI가 설치됐다는 이유로 Pi가 동작한다고 보고하지 않는다. Windows `.venv`를 복사하지 않으며 성능과 GUI 제약을 실기기에서 측정한다.

학교 사진과 학교 최종 평가는 이번 행사에서 제외한다. 인터넷 운영 사진의 경기 결과도 모델/임계값 재튜닝이나 새 독립 정확도로 바꾸지 않는다. PC/Pi의 실제 선택·클릭 일치, 최소0.25초 간격, 경기 시간과 오류 원인은 각각 기록한다. 한 기기의 단발 성공·웹 배포·데모 승패를 전체 완료로 합치지 않는다.
