## 10/27 컴퓨터 브라우저 remote와 데이터 경계

최신 사용자 요청으로 이전 Android 태블릿4대 대신 **컴퓨터 브라우저**에서 인간/AI 표시 화면을 운영한다. 실제 컴퓨터 대수·화면 배치·OS/브라우저 버전·해상도·동시 네트워크 성능은 미확인이다. Chrome은 권장 기준이며 이전 viewport 검사는 현재 현장 배치의 검증이 아니다. 이 전환은 사진 수집·라벨·분할·학교 사진 접근이나 새 정확도 평가를 뜻하지 않는다.

10/27의 이전 기동 요청은 내일 운영 안내와 PC 원격 실행기 켜 두기였다. 가중치 메모리/CUDA 로드와 사진 추론·학습을 구분하며 해당 기동/대기 결과는 STATUS를 따른다. 초기 방 생성→표시/PC 코드 연결 이후에는 아래 최신 방 재사용 절차를 따른다. 운영 중 문제은행이나 승패를 보고 가중치/임계값을 조절하지 않는다.

최신 사용자 승인으로 remote는 초기 A/B 방과 코드를 한 번 연결하고 참가자 교체 때 같은 방을 재사용한다. 인간의 다음 참가자 준비가 종료 round를 lobby로 돌리고 선택·타이머를 비우며, PC 준비 후 인간이 다시 시작한 **새 round**의9장 RGB를 판별한다. 방/토큰/코드는 유지하되 문제·사진 순서·정답·시각·선택 기록은 round별로 구분한다. 새 방은 초기 설정·복구에만 필요하고 legacy는 기존 한 방 한 판이다. 같은 방 반복·사진 재노출을 독립 원본/정확도 표본 증가로 세거나 학습 데이터로 자동 편입하지 않는다. 재사용의 실제 통합/반복 검증은 STATUS를 따른다.

A/B별 인간 화면·AI 표시 화면을 분리하는 remote를 기본으로 구현했으며 이번에는 표시 기기를 컴퓨터 브라우저로 전환한다. PC의 별도 engine이 공개 타일 URL로 사진 바이트를 가져와 메타데이터를 버리고9장 RGB·공개 질문만 모델에 전달한다. URL/타일ID는 전송·순서 연결용이며 라벨·원본 파일명·실제 정답수·정답 파일을 판정 근거로 쓰지 않는다. bot 표시 화면은 서버가 최소0.25초 간격으로 수락한 모델 선택을 진행 중 remote 봇125ms·그 외500ms 폴링과 네트워크 지연 후 읽기 전용으로 표시한다. 양쪽 모두 전체 사진 contain이며 표시 화면에 실제 터치를 주입하지 않는다. 화면 캡처·F8 보정·OS 마우스는 legacy 경로에만 적용한다.

이번 변경은 데이터 수집·주석·분할·학습/임계값 조정이 아니다. Kaggle134장·로컬 시연34장·공개24장·학교0과 기존 P/N/U·해시·그룹/분할을 유지한다. 모델 예측0개도 그대로 제출하고 UI가0개/오답/엔진 단계를 표시하며, 가짜 타일이나 상위k 강제 선택을 추가하지 않는다. Node30·TypeScript·UI ESLint·실제 localhost remote HTTP1개19.126717초와 실제 CUDA 두 방 passed=true는 연결/권한 검증이다. A 건물3선택·B 나무0선택 모두 오답/90초 timeout으로 종료했으며 정확도나 학교 성능 평가가 아니다. 공개 배포·A/B 브라우저 결과는 STATUS를 따르고 물리 패드는0대다. 같은 사진의 A/B 표시·반복 시연은 독립 원본·평가 표본 수를 늘리지 않는다.

## 10/26 후속 요청: 공개 웹 테스트 사진24장

사용자가 웹에서 임의 사진을 내려받아 사이트에서 테스트할 수 있게 해 달라고 요청했다. 기존 비공개 Kaggle 데모를 공개하는 대신 **Wikimedia Commons의 사진24장·6,063,549 bytes·독립 원본/촬영 그룹24개**를 별도로 준비했다. `data/booth/public-web-v1/bank.json`, `images/`, `provenance.json`이 정본이다. 실제 운영 업로드·서버 준비성·브라우저 결과는 [STATUS](STATUS.md)를 따른다. 최초 게시의 빈 문제은행은 이전 상태이며 학교 사진을 추가한 작업이 아니다.

`scripts/prepare_public_booth_bank.py`로 공개API의 사진 후보44장을 제한된 크기로 확보하고 RGB 접촉시트와 모호한 개별 사진을 검토했다. 그중24장을 골라 전체 프레임 JPEG로 재인코딩해 EXIF/GPS/comment를 제거했다. 그림·원본 중복 Apollo11 초상·같은 Paulista 연속촬영 후보는 제외했다. 최종 한 그룹에 한 장이다. 모든 촬영 계보를 찾아내는 자동 유사도 검사는 아니며 단일 Codex 시각 라벨의 한계는 남는다.

| 웹 조건 | 알려진 양성 그룹 | 알려진 음성 그룹 | 미확인 | 최소 준비 |
|---|---:|---:|---:|---|
| 사람3명이상 | 8 | 11 | 5 | 4P7N 충족 |
| 나무3그루이상 | 9 | 11 | 4 | 4P6N 충족 |
| 건물 존재 | 8 | 9 | 7 | 4P7N 충족 |
| 연못 존재 | 7 | 17 | 0 | 4P7N 충족 |

숲·공원의 정확한 나무 총수는 만들지 않고 `treeCount=null`, 명확할 때만 `treeAtLeast3=true`와 최소3그루 근거를 기록했다. 먼 보행자·헬리콥터 탑승자처럼 정확 인원을 확인할 수 없는5장은 null이다. 미확인은 양성·음성 어느 쪽에도 넣지 않는다. 정답은 서버 채점 전용이고 풀이 모델에는 픽셀과 공개 질문만 전달한다.

**CC0 또는 NASA/저자의 사진 자체 public-domain 선언**을 파일별로 확인했다. API `LicenseShortName`뿐 아니라 설명 원문·revision·라이선스 템플릿을 두 에이전트가 나눠 직접 검토했다. 건축물만 PD이고 사진은 CC BY-SA인 Alcatraz/호텔 후보와 관할별/복수 라이선스가 섞인 이란 사원 후보는 제외했다. 2015 Unsplash 버스는 해당 파일의 과거CC0·Commons LicenseReview를 확인했으며 현재 Unsplash 전체가 CC0라는 가정이 아니다. ASTP는 NASA 원본과 Adam Cuerden 복원 모두 크레딧에 남겼다.

`license-reviewed-a.json`, `license-reviewed-a-raw.json`, `license-reviewed-a-templates.json`, `license-reviewed-b.json`, `license-review-summary.json`, `reviewed-labels.json`에 근거를 보존했다. 출처·저자·권리URL·원본ID/SHA1·전달SHA256·변환·시각판단을 각 행에 기록했다. 공개 허용은 이24개 사진의 출처 선언 검토에 한정하며 모든 제3자 권리의 독립 보증은 아니다. **학교0장·프로젝트 추가학습0회·모델 예측을 보고 사진을 고르거나 임계값을 바꾼 작업0회**다. 독립 정확도·40%·학교 일반화의 근거로 쓰지 않는 공개 웹 기능 시연이며 기존 Kaggle134장·v1 분할/가중치는 보존한다.

## 이전 10/26 웹 문제은행과 로컬 Kaggle 데모

사용자의 새 요청으로 사람·봇이 같은 서버 시작 시각에 대결하는 웹사이트도 이 프로젝트 범위에 포함됐다. 운영자가 등록한 사진과 정답 메타데이터는 **문제은행**이며 학습 데이터에 자동 편입하지 않는다. 현재 웹의 정답 수는 사람/건물/연못 2~4칸, 나무 3그루 이상은 3~4칸으로 추첨하며 기존 4P/5N의 난이도 평가와 별개다. 서버는 서로 다른 원본 그룹의 사진 9개를 선택하고 같은 격자를 두 참가자에게 제공한다.

`scripts/prepare_booth_demo.py`로 기존 Kaggle 134장 중 **34장·2,921,524 bytes**를 복사해 로컬 연동 시연 은행을 만들었다. `data/booth/demo-bank.json`에 원래 출처·버전·SHA·개발 split·검토 근거를 기록하고 사진은 `data/booth/demo-images/`의 라벨 없는 opaque 파일명으로 보관한다. 원본 바이트와 v1 manifest/split/모델은 변경하지 않았다. 새 원본 34장을 확보하거나 독립 시험 표본이 34장 늘어난 작업이 아니다.

| 지정 시연 후보 묶음 | 양성 | 음성 | 확인 기준 |
|---|---:|---:|---|
| 사람 3명 이상 | 4 | 7 | 기존 COCO 실물 검토의 verified count |
| 나무 3그루 이상 | 4 | 6 | 10/26 RGB 재검토의 명시적 `treeAtLeast3` |
| 건물 | 4 | 7 | 기존 대상 존재 검토 |
| 연못 | 4 | 7 | 기존 대상 존재 검토 |
| 사람 존재(봇의 별도 지원 조건) | 4 | 7 | 기존 verified count에서 파생 |

위 표는 `topicCandidates`에 적은 최소 후보 묶음이며 다중 라벨을 가진 전체 34장의 대상별 통계와 같다는 뜻은 아니다. 같은 사진을 여러 조건에서 사용하므로 표의 합계가 34장인 것도 아니다. 시연용 선정은 모델 예측을 보고 성공/실패를 고른 것이 아니며, 이미 본 train/val/test 사진을 재사용한 **연동 확인**이다. 새 정확도·학교 성능·40% 달성 검증으로 보고하지 않는다.

나무 양성 네 장은 과수원·숲 입구·목장·양쪽 측백나무 길에서 최소 세 그루의 구별 가능한 실물 교목을 확인했다. 숲의 정확한 총수가 불명확하면 `treeCount=null`, `treeAtLeast3=true`, `treeCountMinimum=3`과 근거를 남겼다. 총수가 3이라고 지어내지 않았다. 음성 여섯 장은 배/바다/투우장/실내 등이며 화분만 있는 경우도 교목 정의에서 제외했다. 이 추가 이진 검토는 기존 ML JSONL의 tree 존재 라벨을 덮어쓰지 않았다.

기존 Kaggle 데모는 **로컬 preview에만** `scripts/import_booth_demo.py`의 관리자 API로 올린다. importer는 localhost 외 업로드를 거부하며 키는 stdin으로 받는다. 원본을 `web/public`이나 배포 산출물에 넣지 않는다. Kaggle 미러만으로 개별 사진의 공개 권리를 일괄 보장하지 못해 최초 게시 때는 빈 문제은행이었다. 이번 공개 테스트는 별도 Commons24장을 사용하며 Kaggle 데모의 공개 허가를 새로 부여한 것이 아니다. 학교는 이번에도 **0장**, 자동 학습·검증·튜닝 접근도 없다.

운영자 웹 메타데이터의 `personCount`, `treeCount`, `treeAtLeast3`, `treeCountMinimum`, `building`, `pond`, 그룹·출처·사용 메모는 서버 채점 전용이다. 미확인은 null이며, 나무 하한 2처럼 세 그루 미만을 증명하지 못하는 정보는 음성으로 바꾸지 않는다. 공개 상태에는 질문·공개 조건·임시 타일 ID/사진 URL과 경기/엔진 상태를 보내고, remote의 AI 선택 인덱스는 bot/engine 역할에만 보낸다. 인간에게 AI 선택 집합을 전달하거나 정답을 어느 풀이 역할에 공개하지 않는다. remote 모델은 전달 사진의 RGB, legacy 모델은 화면 RGB를 판별하며 이미지 ID나 정답 메타데이터로 풀지 않는다.

서버 업로드는 크기·허용 포맷 magic bytes·라벨 정합성을 검사한다. 이것이 사진의 완전한 디코딩이나 수동 라벨의 사실 여부를 보증하지는 않는다. 로컬 데모는 Pillow 실제 디코딩·SHA 검사를 통과했고 웹 업로드는 클라이언트의 이미지 확인과 운영자 검토를 함께 사용한다. 원본 바이트의 EXIF/comment를 자동 제거하는 기능은 없으며 서버 채점용 메타데이터 JSON의 비공개 처리와 구분한다. 이번 데모는 EXIF/GPS 0장·JPEG comment 2장을 확인했다. 등록 자체를 새 학교 평가 완료로 처리하지 않는다.

나무 계수에는 별도 사전학습 **Grounding DINO Tiny** 후보를 추가했다. 가중치는 **689,359,096 bytes(약 689MB)**이며 프로젝트에서 새로 학습한 모델이 아니다. 나무 존재 분류 점수로 수를 만들어내지 않는다. 출처·고정 revision·SHA와 처리 규칙은 [아키텍처](ARCHITECTURE.md)에 기록하며, 이 모델도 40%로 교정되거나 Pi에서 검증된 상태가 아니다.

10/26에는 이 시연 은행의 네 고정 RGB 격자를 실제 CUDA 모델에 넣었다. 건물 한 격자는 맞았고 사람/나무/연못 격자는 실패했다. `runs/booth-model-smoke-v1/report.json`은 사진 재사용의 기능 점검이며 새 독립 정확도나 실제 화면 클릭 결과가 아니다. 최신 경기 규칙인 한 참가자 한 판·첫 완벽 정답 즉시 승리·오답 수정 재제출은 서버 운영 계약이며 이 데이터 라벨/분할을 바꾸는 조건이 아니다.

## 새 목표와 v2 데이터 준비성

사용자 확정 목표는 **정답 4칸·오답 5칸인 3×3 평가에서 정답 선택 집합 완전 일치율을 조건마다 약 40%로 맞추는 것**이다. 나무·건물·연못·사람 존재와 `count >= 2/3/4/5`를 합친 **8개 조건을 각각** 평가하며, 전체 평균이나 인간 승률 40%를 뜻하지 않는다. 4/5 구성은 난이도 평가 기준이며 실제 부스의 모든 문항이 정답 4개로 고정됐다는 뜻은 아니다. 정답 수는 평가기 전용이고 예측기에 전달하거나 상위 4개 강제 선택에 쓰지 않는다.

10/22 평가 계획의 정본 설정은 `configs/calibration-target-v2.json`이다. 허용 오차 수치와 최종 평가 표본 수는 미정이며 **40% 달성·v2 학습·새 v2 사진 확보는 아직 없다.** 현재 자료 준비성은 `runs/calibration-v2/data-readiness.json`에 기록했다. 이 준비성 점검은 기존 manifest와 v1 저장 예측만 재집계한 이력이다. 10/26의 별도 사전학습 나무 모델 확보와 로컬 시연 자료 복사를 새 v2 학습/정확도 검증으로 합치지 않는다.

아래 P/N/U는 조건별 양성/음성/unknown 또는 계수 제외 사진이다. **이 표의 사람 조건은 검출 학습·v1 평가 적격 기준**인 verified·detection_eligible 필터를 적용하며 검토에서 제외한 인원을 음성으로 바꾸지 않는다. 현재 각 행의 원본 그룹이 서로 달라 사진 무재사용 최대 격자 수는 `min(P//4, N//5)`다.

| 조건 | train P/N/U | val P/N/U | test P/N/U | 무재사용 격자 최대 train/val/test |
|---|---|---|---|---|
| 나무 존재 | 29/8/4 | 8/4/2 | 7/7/1 | 1/0/1 |
| 건물 존재 | 16/20/5 | 5/9/0 | 10/5/0 | 4/1/1 |
| 연못 존재 | 2/30/9 | 1/7/6 | 1/10/4 | 0/0/0 |
| 사람 존재 | 14/3/10 | 1/2/2 | 14/4/14 | 0/0/0 |
| 사람 2명 이상 | 10/7/10 | 1/2/2 | 10/8/14 | 1/0/1 |
| 사람 3명 이상 | 7/10/10 | 0/3/2 | 6/12/14 | 1/0/1 |
| 사람 4명 이상 | 4/13/10 | 0/3/2 | 4/14/14 | 1/0/1 |
| 사람 5명 이상 | 1/16/10 | 0/3/2 | 2/16/14 | 0/0/0 |

현재 val은 건물 한 격자만 만들 수 있고 다른 7조건은 한 격자도 만들 수 없다. test의 연못·사람 존재·5명 이상도 4P/5N 한 묶음이 부족하다. 격자 사이 사진 재사용을 허용해도 한 격자 안에는 서로 다른 양성 4장·음성 5장이 있어야 하므로 이 부족은 해결되지 않는다. 반복 조합·순서 변경은 독립 표본 수를 늘리지 않으며, 이미 공개한 v1 test는 v2의 미사용 시험 자료로 전환하지 않는다. 따라서 현재 자료로 각 조건 40%의 달성 여부를 독립적으로 판정할 수 없다.

격자 평가기의 **사람 존재 정답 기준은 검출 적격과 다르다.** 군중을 제외한 `person.present`가 알려져 있으면 정확 인원수가 미검증이어도 존재 정답으로 사용할 수 있어 val 정답은 2P/2N/unknown 1장이다. 위 표의 검출 적격 1P/2N/제외 2장과 혼동하지 않는다. 기존 사람 예측 cache는 이 추가 양성 한 장의 예측이 없어 `missing_prediction_images=1`이며 어느 기준에서도 한 격자를 만들 수 없다.

실제 평가 코드를 기존 val cache에 적용한 `runs/calibration-v2/validation-grid-summary.json`은 조건당 무재사용 100격자를 요청했지만 8조건 모두 `insufficient_data`였다. 건물은 가능한 한 격자의 exact-set 0/1을 기록했다. 이는 새 추론·v2 학습 결과가 아니며 40% 목표 달성을 입증하지 않는다. 한 격자의 0/1을 모든 조건의 독립 성공률로 확장하지 않는다. 최종 목표 허용 오차·시험 표본 수는 계속 미정이다.

v2는 v1을 보존한 별도 데이터·모델 버전으로 준비한다. v1의 모든 선택 원본 SHA·그룹·출처 이미지 ID·부모 계보를 제외하고 새 Kaggle 후보를 확보한 뒤 모델 예측을 보지 않고 라벨을 검토한다. 새 그룹을 train/선택용 val/고정 후 1회 audit용 test로 격리하고 후보 학습 예산을 fit 전에 유한 목록으로 고정한다. 목표 선택은 val에서만 하며 test·학교 자료로 맞추지 않는다. 모델 출력 반전·정답 클릭 누락·정답 파일 조회는 쓰지 않는다.

최소 파이프라인 점검안은 val/test 각각 조건당 무재사용 5격자, 즉 양성 20·음성 25그룹 확보다. 이는 **제안된 작은 pilot이며 최종 표본 수나 통계적 합격 기준이 아니다.** 사람 조건은 각 pool에서 0명 25장, 1~4명 각각 5장, 5명 이상 20장의 검토 통과 65그룹이면 모든 인원 조건의 이 최소 coverage와 경계 사례를 확보할 수 있다. 존재 3대상은 대상별 20P/25N을 확보하되 다중 라벨 사진을 공유해 수량을 줄일 수 있다. 조건 사이 공유 사진의 결과를 서로 독립인 표본처럼 합산하지 않는다. 실제 수집·스크립트 구현은 후속 작업이다.

## 현재 학습용 정본과 검토 결과

원본 COCO 64장과 존재 판별 70장을 합친 **134장·134 연결 그룹**을 확보했다. 통합 검토 정본은 `data/manifests/development-reviewed-split.jsonl`이며 전체 분할은 train 68 / val 19 / test 47이다. 전체 134장을 같은 과제의 완전 주석으로 사용하지 않는다. 실제 모델별 입력과 제외 기준은 다음과 같다.

| 과제 정본 | 전체 기록 | 학습/평가에 쓰는 사진 | 제외·unknown 처리 |
|---|---:|---|---|
| `coco-person-reviewed-split.jsonl` | COCO 64 | 인원·bbox 검토 통과 38장: train 17 / val 3 / test 18 | 군중 8장·모호 18장은 count=null을 유지하고 detection loss/metrics에서 제외 |
| `presence-ml-v1.jsonl` | ADE20K/Places 70 | train 41 / val 14 / test 15 | 대상별 unknown을 loss/metrics에서 마스킹. 사진 전체를 임의 음성으로 바꾸지 않음 |

존재 판별의 현재 라벨 범위는 다음과 같다. P/N/U는 각각 양성·음성·unknown이며 대상마다 합계가 70이다.

| 대상 | 양성 | 음성 | unknown |
|---|---:|---:|---:|
| tree | 44 | 19 | 7 |
| building | 31 | 34 | 5 |
| pond | 4 | 47 | 19 |

존재 판별 원래 56장의 split은 유지했다. 연못의 독립 평가 라벨이 부족하여 **첫 fit 전에** Places 14장을 추가 확보·동일 기준으로 검토하고 val/test에 각각 7장씩 배정했다. 결과를 본 뒤 데이터를 교체한 작업이 아니다. 현재 연못 양성은 train 2 / val 1 / test 1로 여전히 매우 적다. 준비·검토 이력은 `presence-extra-heldout-preparation.json`, `presence-extra-heldout-review-report.json`과 원래 56장의 `presence-ml-review-report.json`에 기록했다. 통합 존재 판별 검증 결과는 `presence-ml-v1-validation.json`이다.

COCO 사람 검토는 **모델 예측을 보지 않은 단일 AI 시각 검토**다. 64장 모두 원본/기존 bbox overlay를 확인했고 어려운 사진은 원본 해상도와 추가 crop으로 검토했다. 통과 38장의 분포는 다음과 같다.

| split | 통과 사진 | 양성/0명 사진 | 정확 인원수 분포 | 통과 bbox |
|---|---:|---|---|---:|
| train | 17 | 14 / 3 | 0명 3, 1명 4, 2명 3, 3명 3, 4명 3, 6명 1 | 37 |
| val | 3 | 1 / 2 | 0명 2, 2명 1 | 2 |
| test | 18 | 14 / 4 | 0명 4, 1명 4, 2명 4, 3명 2, 4명 2, 5명 2 | 36 |

원본의 장난감 Stormtrooper 4개를 사람으로 표시한 이미지 `362131`은 실제 사람 0명으로 정정했다. 이미지 `70896`은 서퍼의 발을 별도 사람으로 표시한 상자를 소유자의 몸 상자와 합쳐 실제 2명으로 정정했다. 나머지 인원 소유관계·상자 완전성이 모호한 경우는 좌표나 수를 억지로 만들지 않고 제외했다. 변경 전 person 전체와 bbox는 새 행의 `annotation_person_original`·`annotation_boxes`에 보존했다. 원본 이미지·기존 manifest·split은 변경하지 않았다.

사람 검토 이력은 `coco-person-visual-review.csv`와 `coco-person-review-report.json`이다. 존재 라벨 검토는 원본 source·경로·해시·person 필드를 보존하며 tree/building/pond만 명시적으로 변경했다. 학습에 사용하는 정본과 프로필의 SHA-256을 고정했으며 사람 검토와 존재 검토를 자동 주석 정답으로 혼동하지 않는다.

## 원본 확보 단계 기록: COCO 샘플

`awsaf49/coco-2017-dataset` 버전 2에서 이미지 **64장**과 원본 인스턴스 주석을 확보했다. 주석 JSON 두 파일의 합은 **489,773,314 bytes**, 이미지 합은 **10,560,523 bytes**다. 사람 주석 수 구간 0/1/2/3/4/5/6명 이상/군중별로 각 원본 split에서 4장씩 추출했다. 이는 라벨 검토용 표본이며 모집단의 자연스러운 인원 분포나 정확도를 나타내지 않는다.

| 자료 | 이미지 수 | 현재 개발 분할 |
|---|---:|---|
| COCO 공식 `train2017`에서 추출 | 32 | 독립 그룹 기준 train 27 / val 5 |
| COCO 공식 `val2017`에서 추출 | 32 | 전체를 개발 test로 보존 |

seed는 42이며 64개의 연결 그룹을 확인했다. **아래 원본 후보 manifest를 처음 만들었을 당시** 검증된 인원 수는 0건이었고 전체 `person.count`를 `null`, 상태를 unknown 56장·crowd 8장으로 기록했다. 이 원본 단계 자료는 현재도 덮어쓰지 않았다. 기존 bbox 수는 `annotation_person_count`라는 검토 전 후보 값이며 `annotation_review=pending_visual_review`다. 이후 검토 통과 38장의 정확 수·bbox는 위 별도 정본에만 반영했다. 나무·건물·연못 라벨도 COCO에서 자동 생성하지 않았다.

실제 산출물은 다음과 같다. 원본과 실제 manifest는 Git에 넣지 않는다.

- `data/raw/kaggle/coco2017/`: 데이터셋 메타데이터, 원본 JSON, 추출 이미지.
- `data/manifests/coco-count-candidates.jsonl`: 분할 전 후보와 검토 상태.
- `data/manifests/coco-count-split.jsonl`: train 27 / val 5 / test 32.
- `data/manifests/coco-count-preparation-report.json`: 원본 URL·해시·크기·추출 구간·검증 결과.

초기 ADE20K 32장·Places365 24장을 합친 후보 단계 목록은 `development-candidates-split.jsonl`의 120장(train 68/val 12/test 40)이다. `development-label-review.csv`와 28장 축소 샘플 점검도 이 초기 단계 기록이다. 현재 ML 정본은 이 후보 목록과 추가 14장에 대한 후속 검토를 반영한 위 134장이다. 원본 후보 단계의 미확정 상태와 현재 적용한 라벨을 구분한다.

## 학교 사진 정책
현재 행사에는 학교 사진을 수집·등록·출제·최종 평가하지 않는다. 사용자의 최신 미사용 결정이 이전 학교 최종 평가 계획을 대체한다. 학교 사진은 지금까지0장이며 열거나 등록하지 않았다.

개발 manifest/로더의 학교 경로·출처 차단은 유지한다. 향후 학교 사용 요청이 다시 생겨도 학교 원본·크롭·증강본을 학습·개발 검증·모델 선택·임계값/전처리 튜닝에 넣지 않는다. 관리자 문제은행은 학습 manifest와 별도이며 이번 인터넷 사진22장도 자동으로 학습에 편입하지 않는다.

원본·실제 manifest·학교 사진·대용량 산출물은 Git에서 제외한다. 원본을 덮어쓰지 않고 변환 버전·출처·사용 조건을 기록한다. 기존 예제 CSV는 이전 뼈대이며 실제 데이터 준비 API와 CLI는 아래 JSONL 스키마를 사용한다. downloader는 기존 파일을 재사용할 때 크기·형식·해시를 확인하며, HTML/ZIP·잘린 응답·잘못된 JSON은 정상 원본으로 저장하지 않는다. 메타데이터의 데이터셋 ref와 버전을 확인하고, 이전 캐시 버전이 다르면 섞어 사용하지 않는다.

| 모호한 대상 | 일부 보임·가림·매우 작은 사람·반사·포스터/화면 속 사람·군중 처리 |
| 연못 | 수영장·호수·분수·하천과의 판정 기준. 학교 연못 모양을 보고 맞추지 않음 |
| 나무·건물 경계 | 관목/화분, 건물 일부·배경·모형의 포함 기준 |

n 범위는 2~5명이다. 이번 사람 기준은 **구분 가능한 실물 사람 인스턴스**, 부분 가림 포함, 원본 bbox 높이 **8px 이상** 및 면적 **64px² 이상**으로 학습 전에 고정했다. 포스터·사진·TV·반사 중복·장난감은 제외한다. 군중과 작은 모호한 사람, 빠진 주석이나 가시 인물 범위가 불확실한 사진은 정확 수 unknown으로 남기고 detection 학습/평가에서 제외한다. 학생 신원·얼굴 식별은 목표가 아니며 이진 사람 라벨과 다른 대상의 미주석을 정확 인원 수·음성으로 바꾸지 않는다.

존재 판별은 실물 나무·야자수, 명확한 고정 건물 외부/지붕/내부, 명확한 작은 정체 수역·인공 양어 연못을 기준으로 검토했다. 관목/화분, 차량/텐트/모형, 호수/수영장/하천과 혼동되는 사진은 대상별 기준에 따라 음성 또는 unknown으로 남긴다. 장면 폴더명이나 마스크 클래스의 미표기만으로 음성을 만들지 않는다. 기준과 개별 판단은 해당 검토 보고서에 보존했다.

검출 기반 계수는 동일 인물의 중복 box를 제거하고 score·NMS 기준을 고정해야 한다. 군중(`iscrowd`) 주석을 곧바로 한 사람으로 세지 않는다. 사람 경계상자 수만 세는 방법의 누락·중복을 샘플로 점검한다. 임의 크롭 후에는 bbox와 사람 수를 다시 계산해야 하므로 원본 인원 수를 그대로 복사하지 않는다.

## 데이터셋을 합치는 기준
Intel의 buildings/forest/street는 대표 장면 라벨이며 나무·건물 존재의 완전 주석이 아니다. forest를 모든 나무의 정의로, street를 건물 없음으로 자동 변환하지 않는다. Human Detection은 사람 있음/없음 보조 자료이며 인원 계수의 주력 자료가 될 수 없다. COCO의 person 인스턴스 주석은 사람 수 과제의 우선 후보이고, 나무·건물·연못은 별도 주석/선별이 필요하다.

데이터셋마다 관측 가능한 라벨만 loss와 평가에 사용하고 나머지는 unknown으로 구분한다. 필요하면 Kaggle 사진 일부를 공통 지침으로 재라벨링한다. 현재 행사에는 학교 사진의 재라벨링·출제·최종 평가를 하지 않는다. 향후 학교 사용을 다시 요청하더라도 학교 자료를 개발·학습 표본에 유입하지 않는 보호 규칙은 유지한다.

## 실제 JSONL 스키마와 API

`src/alpha_captcha/dataset.py`가 한 줄에 JSON 객체 하나를 읽고 검증한다. `load_jsonl`은 구문만 읽으며, 개발에 사용하기 전 `validate_manifest`가 필요하다. `save_jsonl`은 기본적으로 기존 출력 파일을 덮어쓰지 않는다. `grouped_split`은 원본 딕셔너리와 이미지를 바꾸지 않고 분할 결과를 복사해 반환한다. `manifest_stats`는 이미지·연결 그룹·해시 중복·라벨 범위·분할별 통계를 만든다.

| 필드 | 스키마 버전 1의 의미 |
|---|---|
| `schema_version` | 정수 `1` |
| `image_path` | 작업공간 기준 상대 POSIX 경로. `data/raw/kaggle/` 또는 `data/processed/kaggle/` 아래만 허용 |
| `source` | 개발 manifest에서는 `kaggle`만 허용 |
| `dataset_ref`, `dataset_version` | `owner/slug`, 비어 있지 않은 버전 문자열 또는 양의 정수 |
| `image_id`, `group_id` | 데이터셋 이미지 ID와 계보·연속 촬영 등을 묶는 그룹 ID |
| `parent_id` | 선택 필드. 같은 데이터셋의 부모 이미지 ID 또는 `null`; 원본이 manifest에 없어도 형제 파생본을 연결 |
| `sha256` | 실제 파일 바이트의 소문자 64자리 SHA-256 |
| `split`, `original_split` | 선택 필드. `train`/`val`/`test` 또는 `null` |
| `labels` | 정확히 `tree`, `building`, `pond` 키. 각 값은 `true`/`false`/`null` |
| `person.present` | 존재 여부 `true`/`false`/`null` |
| `person.count` | 검증된 0 이상 정수 또는 `null`. bool·음수·소수는 허용하지 않음 |
| `person.count_status` | `verified`, `unknown`, `crowd` |
| `person.boxes` | 개별 비군중 사람의 픽셀 좌표 `[[x1,y1,x2,y2], ...]` 또는 `null` |
| `person.iscrowd` | 군중 주석 포함 여부 bool. true이면 상태는 crowd이고 count는 null |
| `usage_note` | 이용 조건·출처 관련 비어 있지 않은 기록 |

부가 출처·주석 필드도 보존할 수 있다. 현재 COCO 레코드는 폭·높이, 라이선스 ID, 검토 상태와 bbox 개수 후보를 추가로 기록한다. `original_split`은 개발용 정규화 값이다. COCO `val2017`은 원본 폴더명으로 추적하며 이 프로젝트의 test 경계를 유지하려고 `original_split=test`로 기록한다.

`verified`는 count와 present가 일치해야 하며 bbox 목록도 함께 제공하면 count와 목록 길이가 같아야 한다. bbox가 없는 검증된 수동 인원 수는 `boxes=null`로 기록할 수 있다. 일부 bbox만 있는 자료와 이진 사람 라벨은 `unknown` 및 `count=null`로 남긴다. 군중 bbox나 미주석을 1명·0명으로 바꾸지 않는다. bbox 좌표의 유한성·양의 면적·중복과 실제 이미지 경계도 검사한다.

검증 기본값은 파일 SHA-256 계산과 Pillow 픽셀 디코딩이다. API의 `verify_files=False`는 스키마·경로만 확인하는 옵션이며 실제 바이트 검증으로 보고하지 않는다. CLI `data-check`와 `data-split`은 파일 검증을 수행한다. 자동 검증의 `label_truth_verified=false`는 검사기가 수동 라벨의 사실 여부를 독립적으로 증명하지 않는다는 뜻이다. 단일 AI 시각 검토는 사람의 독립 이중 검토를 대신하지 않으며 촬영 계보 완전성까지 보장하지 않는다.

학습 로더는 전체 manifest의 출처·학교 경계·실제 파일·분할 누수를 검사한 뒤 해당 split만 사용한다. `person_model.py`는 `count_status=verified`, `iscrowd=false`, bbox 목록 제공, `person_review.detection_eligible=true`를 모두 요구한다. 검토에서 제외한 26장은 기록에 남지만 detection loss/metrics에는 들어가지 않는다. `presence_model.py`는 대상별 known mask를 사용해 unknown 항목을 학습·평가에서 제외한다.

## 관계 기록과 분할

Kaggle 원본·연속 프레임·유사 장면·크롭·증강본을 그룹으로 묶고 **그룹 단위로 먼저 train/val/test를 분할한 뒤** train에만 증강한다. 현재 분할기는 같은 group_id, SHA-256, 이미지 경로, 데이터셋 이미지 ID(버전 간 포함), 부모·자식·형제 관계를 연결 그룹으로 합친다. 그중 어떤 관계라도 split을 가로지르면 검증에 실패한다. 연속 촬영과 유사 장면은 출처 확인 후 group_id로 연결해야 한다. 시각 검토에서 확실한 중복·연속 프레임 쌍은 확인하지 못했지만 **지각 해시 등의 전체 유사 이미지 검색과 독립적인 촬영 계보 검증은 아직 하지 않았다.**

일반 분할 기본값은 70/15/15·seed 42이며 이미지 수 기준 근사 비율이다. 큰 그룹·공식 경계·부족한 독립 그룹 때문에 비율이나 클래스·인원 구간별 포함을 보장하지 않는다. 통계의 경고와 분할별 양성·음성·unknown 및 검증된 인원 구간을 확인한다. `respect_original_split=True`는 test만이 아니라 지정된 train/val/test를 모두 고정하며, 한 연결 그룹에 상충하는 원본 split이 있으면 실패한다.

현재 COCO 준비 스크립트는 공식 train 후보만 85/15/0으로 분할한 뒤 공식 val 후보를 test로 합치고 전체 누수를 다시 검사한다. 이는 전체 64장을 70/15/15로 임의 섞는 작업과 다르다. 향후 자료를 추가해도 개발 test 경계와 학교 개발 유입 차단을 유지하며 학교 최종 평가는 현재 행사 범위에서 제외한다.

사용자는 학습량·모델 성능을 제한해 의도적으로 정답률을 낮추려 한다. 이번 `configs/limited-baseline-v1.json`은 두 모델 모두 **1 epoch**, 마지막 epoch 사용, 임계값 0.5, 모델 선택·조기 종료·threshold 탐색 없음으로 학습 전에 고정했다. 존재 모델 train 상한 64장에 실제 41장, 사람 모델 상한 32장에 검토 통과 17장을 사용한다. 기존 클래스당 200장·1~3 epoch 가안은 이번 프로필이 아니다. 모호한 사진 제외는 라벨 신뢰도 기준으로 모델 예측을 보기 전에 수행했으며 val/test나 학교 승패를 보고 예산·분할을 조절하지 않는다.

사람 검증 val은 0명 두 장·2명 한 장뿐이고 존재 모델의 연못 val/test 양성도 각각 한 장이다. 검토 통과 표본만의 지표를 전체 후보·학교 사진 정확도로 일반화하지 않는다. 사람 검출기는 **COCO 사전학습 가중치**를 사용하므로 현재 COCO train 유래 사진은 이미 사전학습에 포함됐을 수 있다. 자체 train/val/test 누수가 없다는 것과 사전학습 데이터까지 완전히 독립적이라는 것은 다르다. 이 결과를 처음부터 적게 학습한 모델이나 완전히 미지의 자료에 대한 정확도로 보고하지 않는다. 모델·프로필·checkpoint 해시와 최종 측정값은 STATUS 및 실행 보고서를 따른다.

학교 출처, school 경로, `..` 탈출, 절대 경로, Kaggle 허용 루트 밖으로 향하는 symlink/junction을 개발 manifest와 학습 로더에서 차단한다. 허용 Kaggle 루트 자체가 학교·외부 폴더로 연결된 경우도 실패한다. 이는 경로·출처 선언을 검사하는 것으로 사진 내용의 실제 출처를 증명하지는 않는다. 학교 평가용 로더/별도 manifest는 현재 운영 범위에서 개발하지 않는다. ML에 전달하는 것은 RGB 픽셀이며 경로/파일명은 이미지를 여는 용도다. 정답 파일·정답이 드러나는 파일명·평가 라벨을 풀이 입력으로 사용하지 않는다.

## 재현 명령

프로젝트 루트의 PowerShell에서 실행한다. 현재 학습용 정본 검사는 다음과 같다. 이 명령은 이미 고정한 분할을 다시 섞거나 학습을 재실행하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m alpha_captcha data-check --manifest data/manifests/coco-person-reviewed-split.jsonl --root . --require-split
.\.venv\Scripts\python.exe -m alpha_captcha data-check --manifest data/manifests/presence-ml-v1.jsonl --root . --require-split
.\.venv\Scripts\python.exe -m alpha_captcha data-check --manifest data/manifests/development-reviewed-split.jsonl --root . --require-split
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_dataset.py -v
```

원본 확보 절차는 `scripts/prepare_coco_subset.py --per-bin 4 --seed 42`와 `scripts/prepare_presence_candidates.py`에 남아 있다. 이 준비 스크립트를 실행해도 검토 완료 라벨을 자동으로 재생성하지는 않는다. 실제 학습 명령·출력·평가와 재실행 시 별도 출력 경로는 STATUS를 따른다. 원본 후보 manifest와 현재 ML 정본을 혼동해 바꿔 넣지 않는다.

`data-split`의 다음 예시는 **별도로 만든 train 전용 검토 manifest**를 대상으로 한다. 이 입력·출력 파일은 현재 산출물 이름이 아닌 사용 형식 예시다. 공식 test가 들어 있는 전체 COCO 목록에 원본 split 무시 옵션을 적용하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m alpha_captcha data-split --manifest data/manifests/train-pool-reviewed.jsonl --output data/manifests/train-pool-split.jsonl --root . --seed 42 --ratios 0.85,0.15,0 --ignore-original-split
```

출력 파일이 이미 있으면 CLI는 실패한다. 원본 경계를 모두 보존할 자료에는 `--ignore-original-split`을 생략한다. 현재 분할이 있어도 다른 그룹으로 재배치하기 전에 누수 검증을 통과해야 한다.

## 문제은행과 평가
현재 웹은 사람 3명 이상·나무 3그루 이상·건물·연못 중 한 유형을 선택하고 사진 은행에서 고정 3×3의 서로 다른 사진 9개를 추첨한다. 초기 5개 고정 문제 구상과 현재 구현을 구분한다. 사진 ID·타일 순서·질문 종류·count 비교 연산과 n·정답 집합·버전을 서버 평가 자료에 기록한다. 개발용 난수 재현 평가에는 seed도 기록하며 정답 집합은 채점기만 읽는다.

보고 항목은 대상별 precision/recall, 사람 수 MAE/정확 계수 비율, n명 경계별 오류, 문제 전체 타일 집합 완전 일치율, 미지원/제외 사진 비율이다. Kaggle test와 공개 문제은행 기능 점검은 분리하며 학교 평가는 현재 범위에서 제외한다. remote는 실제 실행 모드·동시 작업 수·CUDA 스트림 수·작업 번호, 예정 선택 간격0.25초·GPU 추론/슬롯 대기·송신/수락·실제 표시 지연·총 시간을 나누어 기록한다. `parallel`과 `serial`의 측정을 섞지 않고 legacy의 실제 OS 타일 클릭 최소0.25초는 별도 측정한다. 무작위 정답 반전이나 클릭 누락으로 정답률을 조작하지 않는다.

9칸 중 정답이 k칸이면 그 k칸을 모두 선택하고 나머지 9-k칸을 모두 선택하지 않아야 문제 전체 성공이다. 타일 오류가 서로 독립이고 동일 조건의 양성 재현율 TPR·음성 정답률 TNR을 적용할 수 있다는 가정에서는 `P(정답 집합 완전 일치 | k) = TPR^k × TNR^(9-k)`다. 이는 가정 기반 설명이며 학교 사진이나 충분한 독립 격자 성공률의 측정값이 아니다. 실제 평가에는 9칸의 확정 라벨과 정답 수 분포가 필요하고, 소수 표본의 타일 지표·음성 비중이 높은 accuracy만으로 전체 성공률을 확정하지 않는다. 시연 점검·독립 성능 측정·가정의 구분은 [STATUS](STATUS.md)를 따른다.
